# 約束の一覧（書き漏れを防ぐ）

約束に書かなかった穴は探されない。対象に当てはまる行を拾い、自分の言葉で「〜できない」「〜だけ」の形に書き直す。
全部を書く必要はない。**当てはまらない行は「当てはまらない」と判断した理由を 1 行残す**（あとで読み返した人が、漏れか判断かを見分けられるように）。

各項目の後ろの `〔…〕` は、外の検査分類との対応（攻め役の見落としを自前の分類だけに閉じないため）:
`API1` 〜 = OWASP API Security Top 10 (2023)（API1 = オブジェクト単位の認可の抜け / API3 = プロパティ単位の認可の抜け / API4 = 資源の無制限な消費 / API5 = 機能単位の認可の抜け / API7 = SSRF）、
`WSTG-認可` = OWASP Web Security Testing Guide の認可の試験（認可の迂回・権限昇格・推測できる id での直接参照）。
対応は目安で、各分類の中身は原典で確かめる。

## A. 誰のデータか（テナント・持ち主）

- A1 別のテナントの行は、1 件取得でも一覧でも検索でも 0 件 〔API1・WSTG-認可〕
- A2 同じテナントでも、自分が属さない下位の単位（部署・顧客・プロジェクト）の行は見えない 〔API1〕
- A3 集計・件数・存在確認（「ある/ない」の返り方の違い）からも、他人の行の有無が分からない 〔API3〕
- A4 他人の id を指定した時の返り方が「存在しない」と同じ（404 と 403 を分けると存在が漏れる） 〔API1〕

## B. 書き込み

- B1 作る時、テナントと持ち主はサーバーが身元から決める。本文や引数の値は使わない 〔API3・WSTG-認可〕
- B2 他人の行は書き換えられない・消せない 〔API1〕
- B3 自分の行でも、持ち主・テナント・役割の項目は後から変えられない 〔API3・WSTG-認可〕
- B4 決められた項目以外を足せない 〔API3〕
- B5 1 回だけのはずの処理（受け付け・付与・消費）が、並べて送っても 1 回しか通らない 〔API4〕

## C. 身元と役

- C1 ログイン無し・不正なトークン・期限切れのトークンでは、どの口も拒否（取得系だけでなく OPTIONS / HEAD / 未定義の口も） 〔API5・WSTG-認可〕
- C2 身元の情報（JWT の中身・クレーム・ヘッダ）に他人の値を混ぜても、他人として扱われない 〔WSTG-認可〕
- C3 自分の役を上げられない・他人に権限を渡せない 〔API5・WSTG-認可〕
- C4 管理用の口・関数は、管理の役以外から呼べない 〔API5〕

## D. 量

- D1 1 回に返す件数に上限がある（上限の引数を省いた時・大きな値・負の値・数字でない値のどれでも） 〔API4〕
- D2 一定時間に返す量・回数に上限がある（上限を越えたらどうなるかも約束に書く） 〔API4〕
- D3 上限は、身元を変えても・口を変えても合算される（複数の鍵・複数の口で分けて越えられない） 〔API4〕

## E. 失敗と記録

- E1 記録や監視が失敗しても、本来の応答は返り続ける（または、止めることを約束に書く）
- E2 記録は、記録される本人から読めない・消せない・書き換えられない
- E3 記録の掃除は自分の古い分だけで、他人の記録を消さない
- E4 エラーの文言に、他人のデータや内部の構造が出ない

## F. 待ち受けと外部

- F1 手元専用の口は、手元のアドレスだけで待ち受ける（IPv6 も）
- F2 外への接続先（webhook・取り込み URL 等）に内側のアドレスを指定できない 〔API7〕
- F3 署名の要る受け口は、署名が無い・古い・別の鍵の物を拒否する

## 約束の書き方

`in/promises.md` には、約束ごとに、この一覧のどの項目を確かめるかを `[...]` で付ける。当てはまらない項目は理由と一緒に書く。`coverage.mjs` がこの形を読んで、確かめた所・試していない所の表を作る:

```markdown
- P1 [A1,A4]: 別のテナントの利用者は、一覧でも 1 件取得でも 0 件 (他人の id は 404)
- P2 [B1,B3]: 注文のテナントと持ち主はサーバーが決め、後から変えられない
- P3 [C1]: トークン無し・不正なトークンでは、どの口も 401
- 当てはまらない [E1,E2,E3]: 記録・監視を持たないアプリ
- 当てはまらない [F2]: 外への接続をしない
```

- 1 行 1 件・番号付き。「〜できない」「〜だけ」で終わる、試験で白黒が付く形
- 誰が（役）・何に（対象）・何をできない（操作）を入れる
- 前提（誰がどのテナントか・どの役か）を約束の上に書く。前提が無いと、攻め役が seed を作れない
