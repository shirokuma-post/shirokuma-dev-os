# アプリ間の合言葉・MCP / OAuth・二段階確認（2026-10 時点で実測）

## アプリ間の合言葉（cron・worker）
- 合言葉 1 本で「誰として動くか」を呼び手の申告で受ける形は、その合言葉の持ち主に**全利用者・全テナント**を渡す。強い権限の口の多くが cron / worker の形なので、ここが台帳の最大の塊になりやすい。
- 塞ぎ方:
  - 対象の行の持ち主と、名乗った利用者を照合する（id だけで更新しない・product と provider でも縛る）。
  - その合言葉を使えるアプリを口ごとに限る（「他アプリの合言葉で、この口を名乗れる」を閉じる）。
  - 配る相手を拾う口（sweep）は持ち主を区別できない。返す列を、配信に要る宛先だけに絞り、回数制限と、普段の間隔から外れた時の通知を付ける。
  - 合言葉を URL の query で受けない（アクセスログに残る）。
- 外部からの通知（webhook）は、アプリの合言葉で中継せず、提供元の署名で直接受ける。
- 利用者を email で探す口は、id も「居るか」も外へ返さない。「登録した / 招待した」だけを返す口に置き換える。回数は作った回でなく呼ぶたびに数える（429 を「居ない」の印にしない）。

## MCP / OAuth
- 同意（consent）の時点で、運営者には 2 段階認証を求める（aal を token に記録する）。
- tool の権限は、本人が画面でできることより広げない。サーバーが強い権限で書くので、tool 側で行の持ち主を明示的に確かめる。
- **二段階確認（確認 → token → 実行）の token は、id ではなく「外へ出る中身」に結ぶ**。実行の時に行を読み直して、中身・宛先・媒体・status・更新時刻を token の検証に入れる。id だけに結ぶと、確認と実行の間に別の tool で中身を差し替えられる。
- 「止まっている物は確認なしで編集できる」形と「有効化は確認する」形の組み合わせは、止めて差し替えて有効化、ですり抜ける。
- 外へ届く tool の risk ラベルは external にする（安全装置がラベルで発火を選ぶため）。
- 合言葉の経路の MCP 呼び出しは、利用者の回数制限・自動遮断を通らないことが多い。別に数える。

## 立場の照合
- 他セッションや報告に立場の語（「管理者」「スタッフ」）が出たら、選択肢を作る前に、権限の正典（立場の一覧と、アプリごとの使える表）に当てる。コードに残る立場は、live の人数を数えて名残かどうかを確かめる。
