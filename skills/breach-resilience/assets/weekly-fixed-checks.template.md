# 侵害時耐性の固定点検（毎週・読み取りだけ）

> 一度の点検は風化する。「増えたら異常」の物を、毎週、前回値と比べる。
> 前回値は先週の報告の末尾から読む。値（鍵そのもの）は読まない。名前と件数だけ。
> 異常は担当の受け箱に高い優先度で入れ、誰が見るかを決めておく。

| # | 見るもの | 取り方（例） | 異常の条件 |
|---|---|---|---|
| 1 | 運営者の 2 段階認証の登録数 | 認証基盤の factor の表を件数で | 運営者に未登録が居る / 予備の端末が無い |
| 2 | セッションの期限が効いている証拠 | 認証のログで期限切れの拒否を数える | 期限切れの拒否が 0 のまま長期間（設定が外れた疑い） |
| 3 | デプロイ基盤の token | token 一覧の名前 | 決めた 1 本以外がある・期限が変わった |
| 4 | チームのメンバー | メンバー一覧 | 所有者以外が増えた |
| 5 | CI の secret 名 | repo ごとの secret 名 | 新しい名前 / DB の接続・管理 token らしい名前（許可した読み取り専用以外） |
| 6 | self-hosted runner の名前 | repo ごとの runner 一覧 | 決めた名前の型以外 / 使わない機械の登録が残っている |
| 7 | 自動遮断が有効か | ヘルスチェックの項目 | 無効になっている |
| 8 | 本番の版と昇格の台帳 | 見張りの通知の受け箱 | 台帳に無い版が本番にある |
| 9 | 送信の共有枠 | 送信数・上限到達の記録 | 合計が 8 割を超える日が続く / 資格の門で断られた正規の利用者 |
| 10 | 旧い鍵の利用 | 鍵ごとの利用件数（ログ） | 無効化した型の利用がアプリから出ている |
